scrollRestore.ts: 列表重建后的滚动位置恢复（纯函数，无直接 DOM 调用）：ScrollRestore 带「重建前像素位置 + 列表顶端第一张可见卡的 id + 视口偏移」；applyScrollRestore 先让调用方 fill 到「原位置 + 一屏」的高度（列表是滚到才建，不补高度 scrollTop 会被夹住），落位**认卡不认像素**——锚点卡已渲染时量它在当前布局的内容偏移（rect 差 + scrollTop，现量真实值），把视口顶对到「内容偏移 − 重建前视口偏移」，与上方未绘制卡的 160px 估算高度无关（旧版按保存的像素 top 落位再按偏移差补偿，估算噪声让两套坐标系差几千像素，锚点差值超一屏上限被放弃 → 「跳转后切回总览落错位置」；像素 top 只在锚点不在 DOM/空锚点时兜底）；上方卡片随后绘制涨回真实高度的位移由浏览器滚动锚定补偿，不要自己写补偿；pickScrollAnchor 取第一张有交集的卡而不是第一张卡；RESTORE_MAX_CARDS=400 是同步补卡上限，再深就退回像素落位、其余交给滚动追加。量测与写入由 sidebarView 注入（anchorContentOffset），所以能在 jsdom 里直接测。
tagBoardView.ts: 标签总览视图，按「标签 → 文档 → 批注」三栏主从跨文档聚合，窄屏降级为单栏 + 面包屑。左栏标签行悬停/右键提供「重命名 / 删除」：重命名走 store.renameTag（目标同名按 tagKey 合并），删除走 store.deleteTag（只摘标签、不删批注），操作前用 getTagUsage 显示影响文件/批注数并二次确认，结果逐文件失败汇总；批量操作期间 mutating 挡住第二次写循环。
editPanel.ts: 浮动编辑面板外壳（FloatingPanel）+ 两个内容包装 openTagEditorPanel / openNoteEditorPanel，侧栏与点击高亮浮层共用。铁律：**面板挂在 document.body，绝不进入 .yh-ov-list 的 DOM**——卡片高度不因开编辑器变化（列表零抖动），整表重绘也删不掉输入框。桌面贴锚点四侧择优（复用 computePopoverPlacement），锚点滚出视口即 dismiss("anchor-gone")；移动端是贴可视区底边的底部卡片（bottom 按 visualViewport 反推软键盘高度，左右留白交给 --yh-sheet-gutter-x）。点外 pointerdown 捕获关闭，但**打开后 700ms 内的 pointerdown 一律忽略**（移动端 WebView 在软键盘弹出时会补发 target=body 的 pointerdown）；**移动端忽略 Escape**（那是输入法在收键盘），桌面 Esc 关闭；关闭原因带出去，标签面板只在非 escape 时 flush() 提交未回车的输入；同一时刻只允许一个面板（module 级 activePanel，开新的先 dismiss 旧的），视图关闭与标注浮层 dismiss 都要调 dismissFloatingPanel 把它带走。
tagInput.ts: 标签 UI 组件，renderTagChips（只读 chip 行）与 renderTagInput（chip + 自定义补全下拉），三端共用；renderTagInput 返回 flush()/focus() 句柄，供弹窗点保存时兜住未回车的标签文本，并处理中文输入法组合态（compositionstart/end + isComposing + keyCode 229，拼音选词不提交、blur 不误提交）。补全候选为带来源的 TagSuggestion（当前文档 OB 标签置顶 / 已用 / OB 全库 / 概念页 / 按内容推荐 / AI 推荐），buildTagSuggestions 为纯函数；本地推荐独立配额最多 3 个、AI 推荐独立配额最多 1 个，都不挤占常规 8 个候选；AI 推荐只有用户点下拉里的「AI 推荐」行才通过 onRequestAi 发请求，加载/失败/空结果状态由组件内部维护，请求在途时关闭下拉会让结果失效、不会晚到重开；quickApply 支持一键沿用当前文档标签；`showSuggestionsOnOpen`（侧栏传 true）让空内容打开即显示候选并在 focus 时兜底重绘，弹窗不传、维持输入后才弹；`initialQuery` / `onQueryChange` 供侧栏重绘后回填未提交文本；空内容折叠为「推荐 3 + 常用 5」（已用标签按使用文件数降序，不再按字典序），其余收进可展开的「还有 N 个候选」，有输入时不做折叠。
stickyNoteLane.ts: 编辑/阅读模式的便签泳道，基于 positioning 布局算法渲染可编辑便签条，支持窄屏自适应。
stickyNoteView.ts: 兼容型便签卡片组件，保留 Markdown 渲染、折叠、删除、编辑动作。
