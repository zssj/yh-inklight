成员清单
annotationCard.ts: 标注详情浮层外壳，md/pdf/epub 三端共用（点击高亮弹出）：只负责定位（桌面走 popoverPlacement 四侧择优；移动端 placeMobile 贴着高亮上/下方就近放置，底部保底 40px 避开手势区与导航栏，键盘弹起时改为贴可视区底，两侧都放不下才撑满）、点外 pointerdown 关闭、Esc、viewport 变化重排；卡片内容与动作行一律交给 cardBody 渲染，本文件不再自绘任何字段——否则又会出现「两处各映射一遍」的漂移（noteType 曾在浮层里丢过）。构造签名是 AnnotationCard(SidebarCard, options)，数据由宿主用 buildCards 取。
popoverPlacement.ts: 浮层定位纯函数（无 DOM），输入划线矩形 + 浮层实测尺寸 + 可用区域，输出 left/top/width/maxHeight/side；四侧都放不下时压缩 maxHeight 由卡片内部滚动，绝不压到选区上；三端共用。
cardModel.ts: 卡片模型纯函数，把一份 sidecar 文档拍平成 SidebarCard（高亮挂笔记、孤儿笔记单独成卡、标签取并集、noteType 从笔记层或高亮层提升到卡片层、relations 取并集去重），无 IO。
cardBody.ts: 卡片 DOM 单点——renderCardBody(root, card, host) 同时服务侧栏列表与点击高亮浮层，head/引用/想法/标签行/关系区/来源行/动作行只在这里产出；CARD_ACTIONS 是动作归属表，每个动作显式声明 inList / inPopover（新增动作必须表态，只写一侧就会漂移），「跳转」只给列表；宿主没给回调 = 该动作此刻不可用，不渲染按钮，绝不造「点了没反应」的控件；标签编辑器也在这里，编辑态由宿主持有（侧栏存 editingTagCardId，重绘不丢），宿主通过 onEditorReady 接管聚焦、滚动、键盘避让与外点关闭；字面相关区同样在这里挂载（host.related 缺省则整块不出现）。
markdownStatsView.ts: 笔记使用统计视图，列出全库 md 笔记并支持跳转/删除；顶部提供 1 天复习（openCount==1）/ 7 天复习（openCount>=2）/ 上月今日 / 去年今日 四张卡片（各 Top 5，日差精确匹配，空卡隐藏）；同一套日历窗口另有一份批注数据源 buildAnnotationBuckets——只按 createdAt 判窗口（批注没有 openCount，**不要**照搬次数条件），关联少的（孤岛）排前面，数据由 main.collectAnnotationReviewEntries 提供、点击走 openAnnotationTarget 精确跳转；回顾行的排版层级固定为「正文 15px/500/两行 > 出处 11px/faint/单行」（.md-stats-review-text / .md-stats-meta），.md-stats-meta 必须有显式字号——它若缺样式会继承 Obsidian 正文默认字号（约 16px），比正文还大，层级倒挂；不传 getAnnotationEntries 则该区块整体不出现。
navigation.ts: 三端跳转单点（md 偏移 / pdf 页码 / epub CFI），侧栏、标签总览与协议回链（main.openSourceLink）共用，第四参 options.newTab 让「从导出笔记点回链」在新标签页打开而不顶掉正在读的笔记；md 分支必须**先等 MarkdownView 就绪**（新开标签页时 leaf.view 常常还不是 MarkdownView，直接取会拿到 null 并静默早退，表现就是「文件开了但停在开头」），定位后还要在 160/520ms 各补一次（新标签页的滚动位置恢复会把定位冲掉）并调用 previewMode.applyScroll 覆盖阅读视图；epub 分支先复用已打开该书的 leaf（view.file 或 viewState.state.file 匹配，含 deferred），避免重复 openFile 二次触发 onLoadFile 造成进度恢复与批注跳转互相覆盖；视图类型常量在本文件内定义，**不要 import EpubReaderView**（会让 esbuild 模块图整体重排，main.js diff 从几百行涨到八千行）。
relatedBlock.ts: 「相关的 N 条」折叠区与「确认关联」选择条的唯一 DOM 实现，侧栏与浮层共用；命中由宿主 load() 提供（插件级 RelationModel 单点 prepare，别在视图里再 new 一份），写入（共享标签/有向关系/断开）全部经宿主回调落库；写入是异步的，落地后调 afterMutate 重绘——浮层是游离节点不会跟着侧栏整表重绘，「已关联」chip 只能靠它刷新。
sidebarView.ts: 右侧 Leaf 总览面板，将 highlight 与关联 note 合并为同一卡片并支持搜索、标签筛选、排序、跳转、删除与导出；顶部搜索/范围（当前文件·全库）/颜色/类型/排序/标签/导出统一收进单一折叠菜单（默认收起，展开态存视图字段 menuOpen，跨重绘保留；开合以 panel.hidden 为唯一硬状态、class 仅作样式，经视图根节点的 click 委托 + menuPanel/menuButton 直连引用切换，不再 querySelector 查找，故按钮被重绘重建或点击相位变化都不会丢收起动作；收起态不占列表高度），有生效筛选时菜单按钮点亮小圆点；卡片标签行可原地编辑，编辑态存在视图字段 editingTagCardId（重绘不丢），仅由点卡片外或 Esc 显式关闭；标签编辑并入按内容推荐项，卡片底部折叠展示字面相关批注（DOM 在 relatedBlock，命中/写入走 plugin.createRelatedHost + confirmRelationTag + removeSharedRelationTag，本文件只给展开态 openRelated），受 contentRelations 设置控制；卡片本体由 views/cardBody 渲染，本文件只给 buildCardHost 的回调（动作/标签/关系）；「提炼成卡片」统一走 plugin.createAtomCardFor，不要在本文件里再写一份（曾与浮层各写一份）；选择条顶部另有四个关系类型（支持/反驳/举例/延伸），选中后额外经 store.addRelation 落一条 self→other 的有向关系，并用 relationAnchorOf 把目标锚点拍成快照（targetOffset/targetPage/targetCfi/targetQuote），关系从此自包含、导出不必回查；关系区也由 cardBody 产出，宿主只给 onJumpRelation（三端定位）/ onRemoveRelation（两侧一起解除）；确认结果落在 tags 字段（无 schema 变更），随标签总览/筛选/obTagBridge 全链路生效；两侧源文件缺失时关联按钮禁用；相关区 details 展开态存视图字段 openRelated，确认后的重绘不折回；移动端编辑态用 utils/keyboardInset 补列表底部留白并把输入框滚入可视区，onClose 与 close() 都清理监听；编辑态期间 requestRender / refreshList 只置 pendingRender 不重绘（退出后补一次），重绘重建仅在用户主动点 + 时聚焦（tagEditorAutoFocus），未提交输入经 pendingTagQuery 回填。
relationModel.ts: 字面关联派生层（与 cardModel 同层），按需内存快照随 store.version 失效；相关批注走短语级匹配（utils/textPhrases）：4 字种子倒排找候选对 → 逐对扩展出最长公共短语 → 按「短语出现在几个源文档里」做文档级稀有度过滤（超过 3 个文档视为通用说法丢弃）→ 同文档只要短语够长够罕见即算相关，跨文档另加术语特征门槛（5 字以上直接放行；4 字短语须含罕见字或术语后缀，且不能是数量词/否定词开头），命中理由取最具体的短语，近邻排除沿用旧规则（md 偏移差<150 / pdf 同页 / epub 同章相邻），同文档降权只影响排序不做门槛；getRecommendedTags 仍基于 textTerms 的「标签→词频」，只推荐用过的标签且冷启动静默；不落盘、不写 sidecar、不升 index 版本。
tagBoardView.ts: 标签总览视图，按「标签 → 文档 → 批注」三栏主从跨文档聚合，窄屏降级为单栏 + 面包屑。
tagInput.ts: 标签 UI 组件，renderTagChips（只读 chip 行）与 renderTagInput（chip + 自定义补全下拉），三端共用；renderTagInput 返回 flush()/focus() 句柄，供弹窗点保存时兜住未回车的标签文本，并处理中文输入法组合态（compositionstart/end + isComposing + keyCode 229，拼音选词不提交、blur 不误提交）。补全候选为带来源的 TagSuggestion（当前文档 OB 标签置顶 / 已用 / OB 全库 / 概念页 / 按内容推荐），buildTagSuggestions 为纯函数；推荐项独立配额最多 3 个，不挤占常规 8 个候选；quickApply 支持一键沿用当前文档标签；`showSuggestionsOnOpen`（侧栏传 true）让空内容打开即显示候选并在 focus 时兜底重绘，弹窗不传、维持输入后才弹；`initialQuery` / `onQueryChange` 供侧栏重绘后回填未提交文本；空内容折叠为「推荐 3 + 常用 5」（已用标签按使用文件数降序，不再按字典序），其余收进可展开的「还有 N 个候选」，有输入时不做折叠。
stickyNoteLane.ts: 编辑/阅读模式的便签泳道，基于 positioning 布局算法渲染可编辑便签条，支持窄屏自适应。
stickyNoteView.ts: 兼容型便签卡片组件，保留 Markdown 渲染、折叠、删除、编辑动作。
