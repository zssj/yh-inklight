成员清单
annotationCard.ts: 标注详情浮层外壳，md/pdf/epub 三端共用（点击高亮弹出）：只负责定位（桌面走 popoverPlacement；移动端 placeMobile 调 computeMobileSheet，**固定占满四边留白之间的区域**，留白与安全区运行时从 CSS 变量 `--yh-sheet-gutter-*` + `env(safe-area-inset-*)` 读取，**代码里不写死任何机型尺寸**；高度只由视口决定，**不要改回按内容测量**，Markdown 异步渲染会让首次测量偏小、卡片被压成一小块）、点外 pointerdown 关闭、Esc、viewport 变化重排；卡片内容与动作行一律交给 cardBody 渲染，本文件不再自绘任何字段——否则又会出现「两处各映射一遍」的漂移（noteType 曾在浮层里丢过）。构造签名是 AnnotationCard(SidebarCard, options)，数据由宿主用 buildCards 取。
popoverPlacement.ts: 浮层定位纯函数（无 DOM）。computePopoverPlacement 供桌面用：输入划线矩形 + 浮层实测尺寸 + 可用区域，输出 left/top/width/maxHeight/side，**完整可见优先，「不遮挡选区」只是偏好**——先找零重叠位置（下/上/右/左），四侧都不行就在上/下两个贴合方向里选偏移最小者，允许压住选区换完整高度，只有可用区比最小高度还矮才贴顶内部滚动（side=overlay）。computeMobileSheet 供移动端用：只按视口算 top/height，留白由 readMobileSheetGutters 从样式表读（`--yh-sheet-gutter-x/-y/-compact` 叠加 `--yh-safe-*`），矮视口自动收紧到 16，不依赖内容测量、不假设机型。
cardModel.ts: 卡片模型纯函数，把一份 sidecar 文档拍平成 SidebarCard（高亮挂笔记、孤儿笔记单独成卡、标签取并集、noteType 从笔记层或高亮层提升到卡片层、relations 取并集去重），无 IO。canExtractAtomCard 是「提炼成卡片」按钮的**唯一门槛**（只看 content 非空白，不限洞见/疑问/提醒），侧栏列表与 md/pdf/epub 三端浮层都必须调它——任一侧自己写条件就会漂移，浮层曾无条件注入回调，导致纯划线能长出空卡。
cardBody.ts: 卡片 DOM 单点——renderCardBody(root, card, host) 同时服务侧栏列表与点击高亮浮层，head/引用/想法/标签行/关系区/来源行/动作行只在这里产出；动作行的图标映射在 ICON_ACTIONS：open-export/atom-card/edit-note/add-note/delete 一律纯图标（与打开导出笔记同款圆形按钮），其余保持文字；纯图标按钮必须给 title，不要新增无 title 的图标动作；CARD_ACTIONS 是动作归属表，每个动作显式声明 inList / inPopover（新增动作必须表态，只写一侧就会漂移），「跳转」只给列表；宿主没给回调 = 该动作此刻不可用，不渲染按钮，绝不造「点了没反应」的控件；标签编辑器也在这里，编辑态由宿主持有（侧栏存 editingTagCardId，重绘不丢），宿主通过 onEditorReady 接管聚焦、滚动、键盘避让与外点关闭；字面相关区同样在这里挂载（host.related 缺省则整块不出现）；展开按钮的尺寸测量按帧批量执行（先统一读、再统一写），避免全库列表逐卡强制布局。
markdownStatsView.ts: 笔记使用统计视图，列出全库 md 笔记并支持跳转/删除；顶部提供 1 天复习（openCount==1）/ 7 天复习（openCount>=2）/ 上月今日 / 去年今日 四张卡片（各 Top 5，日差精确匹配，空卡隐藏）；同一套日历窗口另有一份批注数据源 buildAnnotationBuckets——只按 createdAt 判窗口（批注没有 openCount，**不要**照搬次数条件），关联少的（孤岛）排前面，数据由 main.collectAnnotationReviewEntries 提供、点击走 openAnnotationTarget 精确跳转，点完由 main.markAnnotationReviewed 记「已回看」——buildAnnotationBuckets 跳过当天已回看（reviewedAt）的条目，否则条目永远留在「昨日所写」里；回顾行的排版层级固定为「正文 15px/500/两行 > 出处 11px/faint/单行」（.md-stats-review-text / .md-stats-meta），.md-stats-meta 必须有显式字号——它若缺样式会继承 Obsidian 正文默认字号（约 16px），比正文还大，层级倒挂；不传 getAnnotationEntries 则该区块整体不出现。
navigation.ts: 三端跳转单点（md 偏移 / pdf 页码 / epub CFI），侧栏、标签总览与协议回链（main.openSourceLink）共用，第四参 options.newTab 让「从导出笔记点回链」在新标签页打开而不顶掉正在读的笔记；**md/pdf 选 leaf 一律走 pickNavigationLeaf**：目标文件已在某个标签页里就 reveal 复用，否则 getMostRecentLeaf()（只在主区域/浮窗里找）打开，没有才 getLeaf("tab")；**禁止用 getLeaf(false)**——它是 getUnpinnedLeaf 语义（返回当前活动 leaf），从侧栏或标签总览点跳转时活动 leaf 就是它们自己，文档会被开进那一分组，表现为「所有跳转失效」；md 分支必须**先等 MarkdownView 就绪**（新开标签页时 leaf.view 常常还不是 MarkdownView，直接取会拿到 null 并静默早退，表现就是「文件开了但停在开头」），定位后还要在 160/520ms 各补一次（新标签页的滚动位置恢复会把定位冲掉）并调用 previewMode.applyScroll 覆盖阅读视图；打开失败与视图不就绪都会打 Notice，不再静默；epub 分支**不自己 openFile**：有 CFI 时整体交给 navigateEpub（main.openEpubAtCfi 自己先复用已开该书的 leaf、没有才 getLeaf("tab")），两边各开一个 tab 就会留下两个同书标签页、一个停在进度恢复点一个停在 CFI；无 CFI 时才复用已打开该书的 leaf（view.file 或 viewState.state.file 匹配，含 deferred）；视图类型常量在本文件内定义，**不要 import EpubReaderView**（会让 esbuild 模块图整体重排，main.js diff 从几百行涨到八千行）。
relatedBlock.ts: 「相关的 N 条」折叠区与「确认关联」选择条的唯一 DOM 实现，侧栏与浮层共用；折叠分两层：外层 `<details>` 管「要不要看相关」，**每条摘录自己再有「展开 / 收起」**（超过 RELATED_TEXT_COLLAPSE_LENGTH 才出现，CSS 限 3 行；判定用字符数而非 DOM 测量，因为 <details> 收起时 clientHeight 为 0 会误判）；展开按钮必须 stopPropagation，行本身点击是跳转；命中由宿主 load() 提供（插件级 RelationModel 单点 prepare，别在视图里再 new 一份），写入（共享标签/有向关系/断开）全部经宿主回调落库；写入是异步的，落地后调 afterMutate 重绘——浮层是游离节点不会跟着侧栏整表重绘，「已关联」chip 只能靠它刷新；相关明细行首次展开时才生成，收起态只保留摘要条数，避免全库列表预先建满相关 DOM。

委托 + menuPanel/menuButton 直连引用切换，不再 querySelector 查找，故按钮被重绘重建或点击相位变化都不会丢收起动作；收起态不占列表高度），有生效筛选时菜单按钮点亮小圆点；卡片标签行可原地编辑，编辑态存在视图字段 editingTagCardId（重绘不丢），仅由点卡片外或 Esc 显式关闭；标签编辑并入按内容推荐项，卡片底部折叠展示字面相关批注（DOM 在 全链路生效；两侧源文件缺失时关联按钮禁用；相关区 details 展开态存视图字段 openRelated，确认后的重绘不折回；移动端编辑态用 utils/keyboardInset 补列表底部留白并把输入框滚入可视区，onClose 与 close() 都清理监听；编辑态期间 requestRender / refreshList 只置 pendingRender await prepare；卡片样式另加 content-visibility: auto（styles.css 仅作用于 .yh-ov-list > .yh-ov-card），视口外的卡跳过样式/布局/绘制；首屏之外的卡片正文 Markdown 也延迟到进入列表可视区（提前 400px）才解析（cardBody 的 deferContent 钩子，未渲染时先放原文占位），列表重建前必须 resetDeferredContent 清空观察队列，否则已移除的节点会留在 IntersectionObserver 里泄漏；排序共用模块级 Intl.Collator，查询为空时跳过每卡 haystack 拼接；重建列表后按「视角身份 + 锚点卡」恢复滚动位置（逻辑在 scrollRestore.ts）：listIdentity 只含范围/搜索/筛选/排序/活动文件，**不含 relationModel.ts: 字面关联派生层（与 cardModel 同层），按需内存快照随 store.version 失效；相关批注走短语级匹配（utils/textPhrases）：4 字种子倒排找候选对 → 逐对扩展出最长公共短语 → 按「短语出现在几个源文档里」做文档级稀有度过滤（超过 3 个文档视为通用说法丢弃）→ 同文档只要短语够长够罕见即算相关，跨文档另加术语特征门槛（5 字以上直接放行；4 字短语须含罕见字或术语后缀，且不能是数量词/否定词开头），命中理由取最具体的短语，近邻排除沿用旧规则（md 偏移差<150 / pdf 同页 / epub 同章相邻），同文档降权只影响排序不做门槛；getRecommendedTags 仍基于 textTerms 的「标签→词频」，只推荐用过的标签且冷启动静默；不落盘、不写 sidecar、不升 index 版本；并发 prepare 共享同一次构建（构建期间 invalidate 则丢弃结果重试），builtAt 取构建完成时间，每张卡的 4 字种子表预先建好供所有候选对复用。
scrollRestore.ts: 列表重建后的滚动位置恢复（纯函数，无直接 DOM 调用）：ScrollRestore 同时带像素位置与「列表顶端第一张可见卡的 id + 偏移」，因为卡片高度会随笔记内容变化，只按像素恢复会漂；applyScrollRestore 先让调用方 fill 到「原位置 + 一屏」的高度（列表是滚到才建，不补高度 scrollTop 会被夹住），落位后再按锚点偏移差补偿（<0.5px 不写）；pickScrollAnchor 取第一张有交集的卡而不是第一张卡；RESTORE_MAX_CARDS=400 是同步补卡上限，再深就退回像素落位、其余交给滚动追加。量测与写入由 sidebarView 注入，所以能在 jsdom 里直接测。
tagBoardView.ts: 标签总览视图，按「标签 → 文档 → 批注」三栏主从跨文档聚合，窄屏降级为单栏 + 面包屑。左栏标签行悬停/右键提供「重命名 / 删除」：重命名走 store.renameTag（目标同名按 tagKey 合并），删除走 store.deleteTag（只摘标签、不删批注），操作前用 getTagUsage 显示影响文件/批注数并二次确认，结果逐文件失败汇总；批量操作期间 mutating 挡住第二次写循环。
tagInput.ts: 标签 UI 组件，renderTagChips（只读 chip 行）与 renderTagInput（chip + 自定义补全下拉），三端共用；renderTagInput 返回 flush()/focus() 句柄，供弹窗点保存时兜住未回车的标签文本，并处理中文输入法组合态（compositionstart/end + isComposing + keyCode 229，拼音选词不提交、blur 不误提交）。补全候选为带来源的 TagSuggestion（当前文档 OB 标签置顶 / 已用 / OB 全库 / 概念页 / 按内容推荐 / AI 推荐），buildTagSuggestions 为纯函数；本地推荐独立配额最多 3 个、AI 推荐独立配额最多 1 个，都不挤占常规 8 个候选；AI 推荐只有用户点下拉里的「AI 推荐」行才通过 onRequestAi 发请求，加载/失败/空结果状态由组件内部维护，请求在途时关闭下拉会让结果失效、不会晚到重开；quickApply 支持一键沿用当前文档标签；`showSuggestionsOnOpen`（侧栏传 true）让空内容打开即显示候选并在 focus 时兜底重绘，弹窗不传、维持输入后才弹；`initialQuery` / `onQueryChange` 供侧栏重绘后回填未提交文本；空内容折叠为「推荐 3 + 常用 5」（已用标签按使用文件数降序，不再按字典序），其余收进可展开的「还有 N 个候选」，有输入时不做折叠。
stickyNoteLane.ts: 编辑/阅读模式的便签泳道，基于 positioning 布局算法渲染可编辑便签条，支持窄屏自适应。
stickyNoteView.ts: 兼容型便签卡片组件，保留 Markdown 渲染、折叠、删除、编辑动作。
